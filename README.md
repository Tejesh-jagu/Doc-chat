# DocChat

DocChat is a local-first document workspace for uploading PDF files, organizing them, viewing them, and asking questions about their contents. Its React frontend talks to a FastAPI backend. Document text is extracted and indexed locally; answers are generated by an Ollama model running on your machine.

## Features

- **PDF library:** Upload one or more PDFs, search by filename, sort by date/name/size, rename files, and view storage usage.
- **Folders:** Create colored folders, organize documents, and filter the library by folder.
- **Document chat:** Create and revisit conversations associated with one or more documents. Ask questions, retry assistant responses, and leave feedback.
- **Retrieval and citations:** The backend extracts text page by page, splits it into text chunks, and ranks relevant passages with TF-IDF and cosine similarity. The top five passages are sent to Ollama. Responses include source citations with document names and page numbers when available.
- **PDF viewer:** Read PDFs in the app, navigate pages, zoom, search within a PDF, rotate pages, use full-screen mode, and open a cited page from a citation.
- **Accounts:** Register and sign in with email and password. The login screen also offers a local demo mode. Optional Google Identity Services UI is available when configured.
- **Personalization:** Choose from scenic image and video backgrounds, select the preferred Ollama model, and change your password.
- **Responsive interface:** Dashboard panels adapt for smaller screens.

## Technology

- **Frontend:** React 19, Vite 8, Tailwind CSS 4, PDF.js, React Markdown, Lucide React
- **Backend:** Python 3.12, FastAPI, Uvicorn, SQLAlchemy, SQLite, pypdf, scikit-learn, NumPy, HTTPX, bcrypt, PyJWT
- **Local AI:** Ollama; default model `qwen2.5:3b`

## Requirements

- Windows (the included launcher is `start.bat`)
- Python 3.12
- Node.js compatible with Vite 8 and npm
- [Ollama](https://ollama.com/) for AI-generated answers

## Setup

Open PowerShell in the project directory:

```powershell
cd "E:\Doc chat"
```

### 1. Install backend dependencies

Create the virtual environment and install the backend packages:

```powershell
py -3.12 -m venv backend\venv
backend\venv\Scripts\python.exe -m pip install --upgrade pip
backend\venv\Scripts\python.exe -m pip install fastapi uvicorn sqlalchemy pypdf scikit-learn numpy httpx bcrypt PyJWT email-validator python-multipart
```

### 2. Install frontend dependencies

```powershell
cd "E:\Doc chat\frontend"
npm ci
```

### 3. Install and start the local model

Install Ollama, then download the default model:

```powershell
ollama pull qwen2.5:3b
```

Ollama normally runs as a background service on `http://localhost:11434`. If it is not running, start it in a separate terminal with:

```powershell
ollama serve
```

## Run DocChat

### Windows launcher

After completing setup, double-click `start.bat` from the project directory. It opens separate terminal windows for the backend and frontend.

### Run the services manually

Open two PowerShell terminals in the project directory.

**Terminal 1 — backend:**

```powershell
cd "E:\Doc chat"
backend\venv\Scripts\python.exe run_backend.py
```

The API is available at `http://127.0.0.1:8000`; interactive API documentation is at `http://127.0.0.1:8000/docs`.

**Terminal 2 — frontend:**

```powershell
cd "E:\Doc chat\frontend"
npm run dev
```

Open `http://localhost:5173` in your browser. Vite proxies `/api` requests to the backend on port 8000.

## Using the application

1. Sign in, register an account, or select the demo option.
2. Upload PDF files from the Home or Documents workspace.
3. Wait for each document's status to become **Indexed**. Failed PDF processing is shown as an error.
4. Select the document or documents to use in a chat, then ask a question.
5. Follow citations to open the corresponding document page in the PDF viewer.
6. Use Documents to search, sort, rename, delete, or organize files into folders. Use Settings to select a background, preferred model, or change your password.

## Configuration

The backend reads these optional environment variables:

| Variable | Default | Description |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Base URL for the local Ollama service |
| `DEFAULT_MODEL` | `qwen2.5:3b` | Fallback model name |
| `SECRET_KEY` | Development key in source | JWT signing key; set a unique secret outside local development |

Set a variable in the current PowerShell session before starting the backend, for example:

```powershell
$env:OLLAMA_BASE_URL = "http://localhost:11434"
$env:DEFAULT_MODEL = "qwen2.5:3b"
```

Google sign-in is optional. Configure a Google OAuth 2.0 Web Client ID in `frontend\.env` as `VITE_GOOGLE_CLIENT_ID` (see `frontend\.env.example` for the expected format), then restart the Vite server. The Google Identity Services script and Google Fonts are loaded from Google, so those UI features require an internet connection.

## Data locations and privacy

- SQLite database: `backend\docchat.db`
- Uploaded PDFs: `backend\storage\documents\`
- The configured per-user document storage limit is 500 MB.
- PDF extraction, indexing, and Ollama inference run through the local backend. The document Q&A path sends retrieved document excerpts to the Ollama service configured by `OLLAMA_BASE_URL`; with the default URL, that service is on the same machine.
- This is a local development application, not a production deployment guide. Use a unique `SECRET_KEY`, review authentication and Google sign-in configuration, and configure appropriate network access controls before exposing the backend to other machines.

## API overview

All application endpoints use the `/api` prefix. Full request and response schemas are available in the FastAPI docs at `/docs`.

| Route group | Purpose |
|---|---|
| `/api/auth` | Registration, login, current user, password change, and Google sign-in endpoint |
| `/api/documents` | PDF upload, list/search/sort, rename, move, download/view, deletion, storage statistics, and folders |
| `/api/chats` | Conversation history, messages, retry, and message feedback |
| `/api/system` | Ollama/backend status and user settings |

## Development checks

From `frontend\`:

```powershell
npm run lint
npm run build
```

The frontend scripts are defined in `frontend\package.json`. No backend test suite is currently included.

## Current limitations

- Only PDF uploads are indexed.
- Extraction uses embedded PDF text; scanned/image-only pages need OCR before they can be searched or used for answers.
- Retrieval is local TF-IDF similarity rather than a vector database or embedding model.
- The default AI model must be downloaded in Ollama before it can generate responses. If Ollama is unavailable, the backend can return retrieved excerpts instead of a generated answer.
- Google sign-in requires a configured client ID and should be reviewed before production use.
